# 监控口径与采样

## 采样与上报

- CPU、内存和网速**每秒采样**，默认**每 3 秒压缩批量上传**。
- 卡片每秒显示一个真实采样值，正常连接下约 2～3 秒延迟；浏览器重连后跳过过时的播放积压，Agent 尚未确认的样本仍会尝试补传。
- 磁盘容量、GPU 等较慢指标单独缓存，负载历史在入库时按分钟聚合。
- 上报间隔与卡片显示节奏不同：3 秒批次包含逐秒采样，卡片仍按秒播放；批次到达前不会伪造新的指标。

## 在线与离线

后台「站点设置」中的「离线判定（秒）」默认 180 秒，可设为 30～3600 秒。每个节点实际使用的窗口为「站点离线判定」与「3 倍实时上传间隔」中的较大值。例如上传间隔 60 秒、站点阈值 30 秒时，该节点使用 180 秒窗口，避免在正常上传间隔内误报离线；历史写入间隔不参与此计算。

看板离线状态与「通知」中的离线告警延迟是两个设置，卡片显示离线不代表通知应该立刻发出。离线卡片会保留最后一次数据并显示最近上报时间，不能将这些旧值当作当前状态。

浏览器与面板的实时连接中断，也不等于 Agent 与面板之间中断。页面显示待刷新或数据不动时，应结合 Agent 日志与服务端收到数据的情况判断，见 [Agent 离线排障](/guide/troubleshooting)。

## 内存口径

Linux 内存统计口径：

- 已用内存 = `MemTotal - MemFree - Cached - SReclaimable - Buffers + Shmem`
- Swap 已用量扣除 `SwapCached`

文件缓存不计入已用内存，共享内存计入；面板显示整机内存，而非 NodeFlare 进程占用。

## 历史数据

节点的「历史写入间隔」与「实时上传间隔」分别控制持久化和传输，默认是 60 秒与 3 秒，不会把卡片的逐秒采样改成每分钟更新。负载历史按 1 分钟桶保存，写入间隔决定何时提交批次，不代表每个历史点覆盖的时长。

进入节点详情的「实时」负载图，先读取最近一小时的历史，再追加逐秒实时样本。历史是聚合点，不应看成过去每秒的完整记录；打开页面后生成的实时曲线更密集。真实断线保留空白，不会用虚构的曲线补齐。

浏览器中的实时窗口最多保留最近一小时。刷新页面后重新读取数据库历史，因此刷新前积累的逐秒曲线可能变稀，这是重新载入聚合历史，不是数据库丢失。

历史默认保留 30 天，并进行分层聚合与过期清理，具体粒度见[数据库与备份](/guide/database#历史保留与空间)。延长保留天数不会还原已经聚合或删除的原始样本。

## 延迟拨测

在后台「延迟检测」创建任务，选择 TCP 或 ICMP，设置目标、探测间隔和执行节点。TCP 需要目标端口；ICMP 取决于运行环境的权限及网络是否允许回显请求。

启用分线路延迟显示后，前台按「电信、联通、移动」顺序展示运营商位置，没有数据的位置显示占位，不会把剩余一个或两个结果拉伸成三份数据。先确认任务已经启用、分配给对应节点，再排查目标不可达或权限问题。
