# 常见问题

## 服务启动失败？

先看日志（位置见[默认目录与日志](/guide/platforms#日志位置)），多为端口被占用或数据库连接串有误。

## 面板监听哪个端口？

查看配置文件中的 `bind_addr`，默认 `127.0.0.1:2206`，见[配置](/guide/config)。

## Agent 需要开放入站端口吗？

不需要。Agent 主动出站连接服务端，见[安装 Agent](/guide/agent)。

## Agent 显示离线？

- 确认 Agent 能出站访问面板地址：`curl -I https://你的面板地址`；
- 核对 Agent Token；
- 上报与延迟依赖时钟校准，系统时间偏差过大会有影响。

## Agent 报 HTTP 426，或首页能打开但实时数据不动？

先检查[反向代理](/guide/proxy)的 WebSocket 配置，尤其是 `proxy_http_version 1.1`、`Upgrade` 与 `Connection`。网页能打开只证明普通 HTTP 可达，不能证明 WebSocket 握手成功。再核对实际运行的后端和 Agent 版本及日志，不要仅凭 426 就认定是协议版本问题。

## 公开看板看不到节点？

确认节点未启用「隐藏」，且站点设置中已开启「公开仪表盘」。

## 如何对外访问面板？

脚本安装默认监听 `127.0.0.1`，Docker 容器内需监听 `0.0.0.0:2206`。对外访问时使用 HTTPS 反向代理，并把代理地址加入 `trusted_proxies`，见[反向代理](/guide/proxy)。

## Docker 部署如何查看日志、升级与卸载？

日志：`docker logs -f nodeflare`；升级：`docker compose pull && docker compose up -d`（或 `docker pull` 后重建容器）；卸载：`docker compose down` / `docker rm -f nodeflare`。配置与数据保存在宿主机挂载目录（示例为 `/etc/nodeflare`），更新时沿用原目录，见 [Docker 部署](/guide/docker)。

## Docker 容器启动后立刻退出？

先用 `docker logs nodeflare` 查看错误。常见原因是挂载目录缺少 `config.toml`，或容器用户 `10001:10001` 无法读写目录及配置文件。按 [Docker 部署](/guide/docker#准备配置) 准备配置并设置权限；若使用自定义挂载目录，请替换为实际路径。

## 导出备份报超限？

先备份可保存的数据，评估后缩短历史保留天数，等待后台清理再重新导出。清理后的历史不能靠调大天数找回，见[数据库与备份](/guide/database)。

## 面板显示的内存占用很高？

Linux 下文件缓存不计入已用内存、共享内存计入；面板显示整机内存，而非 NodeFlare 进程占用，口径见[监控口径与采样](/guide/monitoring)。

## Webhook 保存后输入框为空，配置丢了吗？

没有。各渠道的 URL、请求头、请求体可能含密钥，保存后只返回配置状态；留空再次保存会保留原值。测试使用已保存配置。清除请求头需要单独操作并保存；「清除 Bark」等按钮删除对应渠道，取消勾选后保存只停用，见[通知](/guide/alerts)。

## Telegram、Bark 和 Discord 能同时开启吗？

可以，在「通知 → 启用通知渠道」下拉框同时勾选，分别填写配置，再点击统一的「保存设置」。每种渠道当前有一份配置，互不覆盖；不再通过一个 Webhook 预设选择器来回切换服务。

## 测试通知成功，自动告警却收不到？

测试不受自动通知开关限制。请检查「启用通知渠道」是否勾选并保存，以及规则、节点和提醒阈值。未曾上报的新节点不会触发离线告警。Webhook 不跟随跳转，自定义渠道的 HTTP 2xx 也不一定意味着第三方真正完成了推送，见[通知排错](/guide/alerts#收不到通知)。

## 默认 3 秒上传，为什么卡片可以每秒更新？

Agent 每秒采样，默认把多个样本每 3 秒一起上传。前台按秒显示真实样本；实时上传、图表播放和历史写入是三个不同节奏，见[监控口径与采样](/guide/monitoring)。刷新详情页会重载聚合历史，不保留浏览器里临时累积的每秒点。

## 流量什么时候归零，要修改系统时区吗？

不用修改系统时区。节点有独立的「流量重置时区」，默认 UTC，按该时区的重置日零点切换周期，并在后续上报时处理。改重置日或时区会重建周期基线，见[流量统计](/guide/traffic)。

## 缩短历史保留后，数据库文件为什么没有立即变小？

过期清理和历史聚合分批进行；数据库还可能保留可复用空闲页，SQLite 也可能有 WAL 文件。等待维护后检查后台的占用与可回收空间，必要时在低峰期「回收空间」。不要直接删除 WAL，见[数据库与备份](/guide/database)。

## 如何卸载？

服务端用安装脚本 `--uninstall`（保留数据）或 `--uninstall --purge`（删除数据），Agent 加 `--uninstall` 参数，详见[卸载](/guide/uninstall)。Docker 部署见 [Docker 部署](/guide/docker)。

## 远程执行为什么需要 TOTP？

远程执行属高危操作，必须先启用 TOTP 两步验证；单条命令最长执行 10 分钟，离开页面不会中断。

## 勾选「允许远程执行」并保存后，为什么还是不能执行？

该选项改变的是以后生成的安装命令，不能覆盖 Agent 本地的 `--disable-remote`。保存后重新打开节点下载弹窗，在机器上执行新命令；或本地修改服务参数、移除禁用标记并重启。后台同时仍需启用 TOTP，见[节点配置](/guide/nodes#远程执行)。
